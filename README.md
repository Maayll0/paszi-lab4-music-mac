# MusicAccess. ПАСЗИ, лабораторная работа № 4

Музыкальный сервис с регистрацией, поиском и плеером. Названия песен видны всем, а возможность прослушивания зависит от допуска пользователя.

## Запуск

При первом запуске выполните `python scripts/init_env.py` из корня проекта. Скрипт создаст локальный файл настроек. Затем запустите сервисы и откройте http://localhost:8080.

```sh
docker compose up --build
```

## Мандатный доступ

У песен и пользователей три уровня: Public (1), Confidential (2) и Secret (3). После регистрации пользователь получает Public. Сервер отдаёт аудио, если допуск пользователя не ниже уровня песни.

| Допуск пользователя | Песня Public | Песня Confidential | Песня Secret |
|---|---|---|---|
| Public | Доступно | 403 | 403 |
| Confidential | Доступно | Доступно | 403 |
| Secret | Доступно | Доступно | Доступно |

## Безопасность

- **Запросы к БД.** SQLAlchemy передаёт значения отдельно от текста SQL. Поиск ограничен 100 символами на поле и воспринимает `%` и `_` как обычные символы.
- **Сессии.** После входа браузер получает случайный токен в cookie с `HttpOnly` и `SameSite=Lax`. Сервер проверяет хеш токена и срок сессии при обращении к защищённым ресурсам. В режиме production включается `Secure` и требуется HTTPS. Локальный стенд работает по HTTP.
- **Изменение данных.** Сервер проверяет специальный заголовок запроса. Для выхода и удаления аккаунта он дополнительно сверяет CSRF-токен сессии.
- **Файлы.** Перед выдачей песни сервер проверяет полный путь из записи БД. Он разрешает чтение только файлов внутри каталога аудио.
- **Пароли.** Сервер хранит хеш Argon2id с отдельной случайной солью для каждого пароля. Поэтому готовые таблицы хешей нельзя использовать сразу для всех пользователей.
- **Входные данные.** Pydantic проверяет поля запросов, в том числе формат логина, адрес почты и требования к паролю. При регистрации, входе и удалении аккаунта лишние поля отклоняются.
- **Выдача аудио.** Перед передачей файла или его части сервер проверяет сессию и сравнивает уровни пользователя и песни из БД. Без действующей сессии он возвращает 401, при недостаточном допуске возвращает 403.
